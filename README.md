# Практика: наблюдаемость агента поддержки интернет-магазина в Langfuse

Мы развернем Langfuse локально в Docker, запустим агента поддержки вымышленного интернет-магазина «Орбита» сначала без наблюдаемости, затем с трассировкой, разберем трассу и сравним две версии системного промпта по автоматической оценке.

Ориентировочное время практики - 40-50 минут.

## Что понадобится

- Docker и Docker Compose (Docker Desktop на macOS и Windows);
- Git;
- Python 3.12 или новее и установленный `uv`;
- API-ключ LLM провайдера.

Свободного места под образы и данные Langfuse - около 5 ГБ, порт 3000 должен быть свободен.

## 1. Развернуть Langfuse локально в Docker и получить ключи

Langfuse - open source, поэтому весь контур наблюдаемости можно держать у себя. Разворачиваем его рядом с демо:

```bash
git clone --depth=1 https://github.com/langfuse/langfuse.git
cd langfuse
docker compose up -d
```

Поднимается несколько контейнеров: веб-приложение, фоновый worker, PostgreSQL для метаданных, ClickHouse для трасс, Redis для очередей и MinIO как S3-совместимое хранилище.

Дождитесь готовности веб-контейнера:

```bash
docker compose logs -f langfuse-web
```

Ожидаемо: через 2-3 минуты в логе появится строка `Ready`. Выйдите из просмотра логов сочетанием `Ctrl+C`.

Проверьте состояние контейнеров:

```bash
docker compose ps
```

Ожидаемо: все сервисы в состоянии `running` или `healthy`.

Откройте `http://localhost:3000` и выполните первичную настройку:

1. зарегистрируйте локального пользователя (данные остаются в вашей базе);
2. создайте организацию, например `otus`;
3. создайте проект `shop-support`;
4. откройте Settings → API Keys и создайте пару ключей;
5. скопируйте `pk-lf-...` и `sk-lf-...`.

Секреты в `docker-compose.yml` помечены комментарием `CHANGEME`. Для локального демо их можно оставить, но для любого общего стенда обязательно замените `NEXTAUTH_SECRET`, `SALT` и `ENCRYPTION_KEY` на длинные случайные значения.

## 2. Запустить агента магазина без наблюдаемости

В нашем репозитории создайте локальный файл с переменными окружения:

```bash
cp .env.example .env
```

Заполните `.env`:

```dotenv
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_BASE_URL=http://localhost:3000
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-4o-mini
```

`LANGFUSE_BASE_URL` указывает на локальный Langfuse. Не показывайте значения ключей на экране и не добавляйте `.env` в Git.

Создайте виртуальное окружение и установите зависимости:

```bash
uv sync
```

Проверьте интерфейс программы:

```bash
uv run python src/agent.py --help
```

Ожидаемо: `uv` запустит программу и покажет параметры `--question`, `--prompt-version`, `--user-id` и `--session-id`.

Теперь запустим агента с отключенной отправкой трасс, не меняя код:

```bash
LANGFUSE_TRACING_ENABLED=false uv run python src/agent.py \
  --prompt-version v1 \
  --question "Можно вернуть наушники через 10 дней после получения заказа?"
```

Ожидаемо: в терминале появится ответ о возврате в течение 14 дней. В Langfuse новой трассы нет.

Обсудите, что можно понять из такого запуска:

- финальный текст клиенту известен;
- не видно, какое правило магазина нашла база знаний;
- не видно входа, длительности и стоимости вызова модели;
- нельзя связать обращение с клиентом, заказом и версией промпта;
- качество приходится оценивать вручную по отдельному ответу.

Это исходная точка: агент работает, но причины его поведения не наблюдаемы.

## 3. Добавить связанную трассу и метаданные

Откройте `agent.py` и найдите три уровня инструментирования:

1. `@observe(name="support-agent")` создает корневую операцию агента;
2. `@observe(name="knowledge-search")` фиксирует поиск по правилам магазина как вложенный шаг;
3. `from langfuse.openai import OpenAI` автоматически записывает обращение к OpenAI как generation. Ключ и модель берутся из `src/variables.py`.

Контекст `propagate_attributes(...)` добавляет ко всей трассе:

- `user_id` - идентификатор клиента магазина;
- `session_id` - переписка по конкретному заказу;
- `version` - версия системного промпта;
- теги и метаданные для фильтрации.

Запустите версию `v1` с включенной наблюдаемостью:

```bash
uv run python src/agent.py \
  --prompt-version v1 \
  --user-id customer-2045 \
  --session-id order-A-1043 \
  --question "Можно вернуть наушники через 10 дней после получения заказа?"
```

Ожидаемо: агент напечатает ответ, а после `flush()` данные уйдут в локальный Langfuse.

В интерфейсе на `http://localhost:3000` откройте Tracing → Traces и выберите свежую трассу `support-agent`. Проверьте:

1. вопрос клиента и итоговый ответ корневой операции;
2. вложенную операцию `knowledge-search` и найденное правило возврата;
3. generation `compose-support-answer`;
4. имя модели, сообщения, параметры, usage и latency;
5. `user_id=customer-2045`, `session_id=order-A-1043`, тег `v1`;
6. score `source-present`.

Для `v1` ожидаемое значение `source-present` - `false`: промпт не требует указывать источник. Если модель самопроизвольно добавила точную строку источника, повторите запуск с другим вопросом - это наглядно показывает вероятностную природу LLM.

Важно: Langfuse получает входы и выходы декорированных функций, то есть переписку с клиентом. Даже на своей инфраструктуре заранее определите правила маскирования персональных данных и при необходимости отключайте захват через `capture_input=False` и `capture_output=False`.

## 4. Диагностировать запуск и сравнить оценки двух версий

По трассе `v1` сформулируйте диагноз:

- поиск вернул релевантное правило возврата;
- модель получила правильный контекст;
- технической ошибки нет;
- требование указывать источник отсутствует в системном промпте;
- проблема находится в версии инструкции, а не в поиске или провайдере модели.

Запустите улучшенную версию:

```bash
uv run python src/agent.py \
  --prompt-version v2 \
  --user-id customer-2045 \
  --session-id order-A-1043 \
  --question "Можно вернуть наушники через 10 дней после получения заказа?"
```

Ожидаемо: ответ заканчивается строкой `Источник: правила магазина Орбита`, а score `source-present` равен `true`.

Теперь проверьте поведение при отсутствии данных в базе знаний:

```bash
uv run python src/agent.py \
  --prompt-version v2 \
  --user-id customer-2045 \
  --session-id order-A-1043 \
  --question "Можно ли обменять наушники на другую модель?"
```

Ожидаемо: шаг `knowledge-search` сообщает, что статья не найдена, а агент не выдумывает правило обмена и предлагает обратиться в поддержку.

В Langfuse:

1. отфильтруйте трассы по тегу `agentops-open-lesson`;
2. сравните `version=v1` и `version=v2`;
3. сопоставьте вопросы, найденный контекст, ответы, latency и usage;
4. убедитесь, что все обращения собраны в сессии `order-A-1043`;
5. сравните значения `source-present`.

### Итог практики

Мы получили минимальный цикл AgentOps на собственной инфраструктуре:

1. развернули Langfuse локально;
2. записали полный путь обращения клиента;
3. локализовали причину дефекта по вложенным шагам;
4. изменили версию промпта и подтвердили улучшение измеримой оценкой.

Для production следующий шаг - собрать набор типовых и проблемных вопросов клиентов, прогонять обе версии по этому набору и блокировать выпуск при регрессии качества, задержки или стоимости.

## Остановить стенд после занятия

```bash
cd <путь до склонированного langfuse>
docker compose down
```

Команда `docker compose down -v` дополнительно удалит тома с трассами - используйте ее, если стенд больше не нужен.
